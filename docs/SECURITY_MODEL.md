# WireShield Security Model

## 1. Cryptographic Foundations
WireShield uses modern cryptographic primitives enforced by the **WireGuard** protocol:
* **Key Exchange & Public Key Cryptography**: Curve25519 (ECDH) as specified in RFC 7748.
* **Symmetric Encryption & Authentication**: ChaCha20-Poly1305 (RFC 7539 / RFC 8439 Authenticated Encryption with Associated Data - AEAD).
* **Hashing & Key Derivation**: BLAKE2s (RFC 7693) and HKDF.
* **Post-Quantum Resistance**: Optional 32-byte pre-shared symmetric keys (`PresharedKey`) mixed into the Noise protocol handshake.

## 2. Zero-Trust Key Lifecycle
* **Client-Side Generation**: Private keys are generated entirely inside the Android device using `java.security.SecureRandom`.
* **Zero Private Key Transmission**: The client private key never leaves the device's private app storage. The backend and VPN servers only receive the Base64-encoded Curve25519 **Public Key**.
* **Key Regeneration**: Users can regenerate their key pairs at any time from the app Settings.

## 3. Kill Switch & Network Monitoring Watchdog Architecture
WireShield implements an active, multi-layered Kill Switch backed by a dedicated **Network Monitoring Service (`NetworkMonitorService`)**:

1. **Active Drop Detection Watchdog**:
   * Runs continuous background health checks probing socket activity, peer handshake responsiveness, and physical network state transitions.
   * Detects silent packet drops, gateway timeouts, network roaming, and unexpected connection disruptions.
2. **Emergency Blackhole Lockdown Interface**:
   * If a connection drop occurs, WireShield does NOT simply teardown the TUN interface and expose raw interfaces.
   * Instead, it instantly transitions into a dedicated **Blackhole Lockdown TUN** with:
     * Full route isolation: `0.0.0.0/0` and `::/0`
     * Non-routable blackhole IPs (`10.255.255.2/32`, `fd00:dead:beef::2/128`)
     * Sink DNS routing (`10.255.255.1`)
     * OS-level blocking (`setBlocking(true)`)
   * All outbound network packets generated by any app on the device are swallowed and discarded at the kernel TUN layer. Zero plain-text packets leak to the ISP.
3. **Auto-Recovery & Safe Restoration**:
   * The watchdog continuously probes when the network and server become reachable again.
   * Once validated, the secure encrypted WireGuard tunnel is automatically reconstructed, lifting the lockdown with zero user friction.
   * Users can also manually unblock internet traffic via the persistent system notification or app UI.

## 4. Leak Mitigation Guarantees

### DNS Leak Protection
* Internet Service Providers (ISPs) often snoop on unencrypted DNS queries even when VPN tunnels are active.
* WireShield prevents this by overriding the device's resolver table inside the VPN interface with trusted privacy DNS servers (`1.1.1.1`, `9.9.9.9`, or user-specified custom DNS).
* Any DNS query directed to port 53 is encapsulated and forced through the encrypted WireGuard UDP tunnel.

### IPv6 Leak Protection
* Many mobile carriers assign dual-stack IPv4/IPv6 addresses. If a VPN only routes IPv4, IPv6 requests bypass the tunnel in cleartext.
* WireShield intercepts IPv6 traffic by assigning a local IPv6 tunnel address (`fd00::2/128`) and adding the catch-all route `::/0`.

## 5. Backend & Server Security
* **Admin Token Authentication**: All mutating endpoints (`POST /api/servers`, `DELETE /api/servers/:id`) require HTTP Bearer tokens.
* **Rate Limiting**: Defends public endpoints (`/api/client/config`) against IP allocation exhaustion and brute-force key scraping.
* **Kernel Network Hardening**: Strict reverse path filtering (`rp_filter = 1`), TCP SYN cookie protection, and rejection of ICMP redirects.
